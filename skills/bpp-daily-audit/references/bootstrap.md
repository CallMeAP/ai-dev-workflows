# One-time bootstrap

Run once, before the first dry-run. Both steps are outward-facing GitLab writes — confirm with the
user before executing.

## 1. Reports repo

```bash
glab api --method POST /projects \
  -f name="bpp-audit-reports" \
  -f path="bpp-audit-reports" \
  -f namespace_id="$(glab api /groups/lipso%2Fclients%2Fbrokernet | jq -r .id)" \
  -f description="Daily automated audit of BPP/Brokernet commits — reports, escalations and finding ledger. Generated by the bpp-daily-audit skill." \
  -f visibility="private" \
  -f initialize_with_readme=true
```

Then clone to `~/Entwicklung/bpp/bpp-audit-reports` and create the layout:

```
README.md
ledger/state.json          {"schema":1,"repos":{},"jira":{},"deferred":[],"nuget":{}}
ledger/findings.jsonl      (empty)
reports/.gitkeep
escalations/.gitkeep
rules.md                   the audit's checklist — without it a run aborts
```

### README.md content (required sections)

The README is the entry point for anyone who finds this repo cold. It MUST carry:

1. **What this repo is** — generated output only; nothing here is hand-written, do not edit reports
   or the ledger by hand.
2. **Where the skill that writes it lives** — the published mirror:
   <https://gitlab.com/lipso/internal/agentic-coding-knowledge/-/tree/main/personal-workflows/apittrich/skills>
   (skill directory `bpp-daily-audit`). Canonical source is the local
   `~/.claude/skills/bpp-daily-audit/`, published via the `sync-my-skills` skill. Anyone wanting to
   run or change the audit downloads the skill from that mirror.
3. **How it is currently run** — state honestly whichever is true at the time: today it is run **by
   hand** from a Claude Code session with `/bpp-daily-audit`.
4. **TODO — automate this audit.** Explicitly listed as open: the run is to move to an unattended
   daily systemd timer at 12:07 invoking `claude -p "/bpp-daily-audit"`. Until that TODO is closed,
   a missing report for a given day means nobody ran it, not that there was nothing to report.
5. **Layout** — what `reports/`, `escalations/` and `ledger/` hold.
6. **How to read a finding** — pointer to the fingerprint/dedup rules so a reader understands why a
   known finding stops reappearing.

## 2. `audit-bot` group label

A **group** label on `lipso/clients/brokernet` is inherited by every project in the group and its
subgroups (`servo/`, `callidus/`) — create it once, not 25 times.

```bash
glab api --method POST "/groups/lipso%2Fclients%2Fbrokernet/labels" \
  -f name="audit-bot" \
  -f color="#8E44AD" \
  -f description="Findet oder behebt ein Finding des bpp-daily-audit — egal ob der MR vom Audit automatisch geoeffnet oder von Hand geschrieben wurde. Review wie jeder andere MR; wird nie automatisch gemerged."
```

Existing group labels for reference: `devops`, `main-deployment`, `qodana`, `staging-deployment`.

## 3. Exclude the reports repo from promotion sweeps

`bpp-audit-reports` matches `^bpp-` and will otherwise appear in every
`bpp-promote-dev-to-staging` preview. Add it to that skill's always-exclude list next to
`bpp-cca-connector-internal`.

`bpp-bump-shared-version` needs no change — it only discovers `bpp-*` repos whose
`BPP.*/Directory.Build.props` contains `<BppSharedVersion>`, which a reports repo has not.

## 4. Run state dir

```bash
mkdir -p "$HOME/.local/state/bpp-daily-audit"
```
